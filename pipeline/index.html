Pipeline

From documents to a governed graph

Every stage of the ontorag CLI, what it reads and writes, and who decides: a language model, deterministic code, or a person.

Install and configure

pip install ontorag            # Python 3.12 or later
pip install "ontorag[pdf]"     # optional extras: pdf, pageindex, llamaindex, docling, unstructured, neo4j
ontorag doctor                 # check ingest engines, vector extension and LLM settings

Stages that call a language model use any OpenAI-compatible endpoint. By default that is OpenRouter:

export OPENROUTER_API_KEY=…
export OPENROUTER_MODEL=~deepseek/deepseek-v4-flash-latest   # any model id the endpoint accepts
# local models: point the same client at ollama
export OPENROUTER_BASE_URL=http://localhost:11434/v1 OPENROUTER_API_KEY=ollama

Flags override the environment: --model, --base-url, --api-key, and -j for concurrency.

Stages

#StageCommandDecided byProduces
01Ingestontorag ingestCodeDocuments and chunks (JSON, JSONL), hashed so unchanged files are skipped. Engines: builtin (Markdown, text, HTML, EPUB, PDF), PageIndex, LlamaIndex, Docling, Unstructured.
02Baselinesontorag init-schema-card
ontorag register-ontology		PersonThe initial schema card, composed from baseline ontologies taken from the catalog or registered locally.
03Proposeontorag extract-schemaModelProposed classes, properties and events for each chunk, aggregated.
04Alignontorag align-schemaModelFor each proposed term: reuse, extend or new, with a rationale. Resumable.
05Mergeontorag build-schema-cardCodeThe next schema card, via a deterministic merge.
06ReviewEdit or diff the card; commitPersonAn approved card. The Hub provides an editable diff for this step.
07Exportontorag export-schema-ttlCodeThe ontology as OWL/RDFS Turtle.
08Extractontorag extract-instancesModelInstances limited to the approved schema, each with provenance mentions (Turtle).
09Indexontorag indexCodeA local vector index (SQLite), optionally quantised and shippable.
10Packageontorag build-datasetCodeThe published dataset format: per-source chunk files, entity index, source registry, manifest. Run automatically at the end of run-stage extract.
11Publishontorag hub pushPersonThe dataset in a GitHub repository, packaged first if needed. Private by default; never uploads DTOs or secrets.

For a dataset directory, ontorag run-stage propose and ontorag run-stage extract run the governed stages incrementally: only new documents reach the model, and --full reprocesses everything. extract ends by packaging the dataset, so it can be served straight away.

Serve

CommandWhat it serves
ontorag sparql-serverA SPARQL endpoint over the ontology and instances (port 8890).
ontorag mcp-serverA knowledge-graph MCP server (port 9010) over local Turtle files, a remote SPARQL endpoint, or Neo4j. Tools: sparql_select, sparql_construct, describe, list_by_class, outgoing, incoming, mentions.
ontorag ontology-mcpThe baseline ontology catalog as MCP (port 9020).
ontorag load-ttl, sparql-updateLoad into, or update, a Blazegraph triple store in named graphs.
ontorag load-neo4jProject instances into a Neo4j property graph.

To serve a published dataset directly from GitHub, use ontorag-mcp.

What each run leaves behind

Every stage writes plain files: chunk JSONL, proposal and alignment JSON, schema cards, Turtle. Each can be diffed, reviewed and committed. The build vocabulary can record the lineage: which run, with which model and software version, consumed which files and produced which artifact. The provenance ontology ties each extracted fact to its passage.
