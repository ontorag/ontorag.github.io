Ontology-first retrieval

Retrieve meaning, not paragraphs.

OntoRAG turns documents into a knowledge graph. The graph's schema is aligned to existing ontologies and reviewed by people, and every fact is linked to the exact passage it came from. Agents query it over SPARQL and MCP, so answers are grounded in structure and cite their sources.

Language models propose. Code decides. People govern.

Build, publish, serve

Build

The ontorag CLI ingests documents. It proposes a schema aligned to baseline ontologies, and after review it extracts instances with page-accurate provenance.

Publish

The result is a dataset: a git repository with a manifest, the graph, text chunks and embeddings. It is versioned, reviewable and readable without a database.

Serve

MCP servers and a SPARQL endpoint expose the graph to agents. Answers come back as ontology facts plus the passages that support them.

Why not just RAG?

Retrieval-augmented generation finds text and paraphrases it. That breaks down when a domain has structure, such as types, rules and relations, or when answers must be traceable and consistent.

Classic RAGOntoRAG
What is retrievedSimilar paragraphsEntities and relations, with the passages that support them
SchemaImplicit; the model invents fieldsExplicit, aligned to existing ontologies, reviewed before use
CitationsA chunk id, if anySource, printed page, section and quote for every fact
ConsistencyDepends on which chunks come backThe same graph answers the same question the same way
ChangeRe-embed and hopeSchema changes are proposals, reviewed and versioned in git
AccessAll or nothingComposed per source: each consumer sees only the sources it holds
