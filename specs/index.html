Specifications

Open specifications

Three small, versioned specifications define what an OntoRAG dataset is, so any tool can produce or consume one. All are CC0 and validated in CI.

Dataset format 0.1

How a published dataset is laid out: manifest.json, graph, entity index, chunks and embeddings, one file per pack. Defined as JSON Schemas.

https://ontorag.org/vocab/dataset/0.1/

Build vocabulary orag: 0.2.0

What the pipeline produces and how: datasets, schema cards, graph and index artifacts, build runs, baselines, alignment decisions, governance status.

https://ontorag.org/vocab#

Provenance and citation ontology orp: 0.1.0

Where each fact comes from and how to cite it. Also defines per-source packs, and how they compose and scope access.

https://ontorag.org/provenance#

The two vocabularies are thin profiles over W3C and SPAR standards (PROV-O, Web Annotation, VoID, Dublin Core, CiTO) and share PROV-O. An orag:Dataset is a void:Dataset whose subsets are orp:Packs, and an orag:BuildRun consumes orp:SourceFiles.

What makes a dataset OntoRAG-compliant

  1. manifest.json validates against manifest.schema.json, and every chunk, embedding and entity record validates against its schema.
  2. The graph named by ontology.graph parses as RDF, and entity IRIs sit under ontology.base_iri, which should be dereferenceable.
  3. Every embedding has the manifest's dim, and every chunk has exactly one vector with the same id.
  4. Provenance uses orp: and passes its SHACL shapes: each mention targets a source file, and each pack has one source and one named graph.
  5. If the dataset has packs, they follow the composition rules: each pack's graph says what its source says, attestations live with their evidence, and resources outside graphs carry orp:inPack.

Domain ontologies

The specifications are domain-neutral. Each dataset aligns to baseline ontologies for its domain. The reference catalog includes rpg-schema for tabletop role-playing games, alongside schema.org, FOAF, Dublin Core and several game-system vocabularies. See the catalog.

Versioning

Namespaces are stable, and each release also has a versioned IRI that resolves to its own copy (for example ontorag.org/provenance/0.1.0). A manifest's ontorag field states the dataset format version it follows. Changes are listed on each specification page.
